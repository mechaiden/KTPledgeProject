Who I am: Robert, UGA engineering undergrad, frontend developer on a KTP (Kappa Theta Pi) team project. Teammate Aiden owns the backend. I build mainly with Claude Code on my Windows PC; I use chat assistants for planning.

THE PRODUCT
Shoebox — "We replace the shoebox." For small business owners and freelancers without a bookkeeper (food trucks, salons, contractors). Promise: snap a receipt, get organized spending data, only step in when you need to. Users upload receipt photos/PDFs; the backend reads them with an OCR model (ByteDance Dolphin 1.5), extracts merchant/date/items/subtotal/tax/total, auto-categorizes into 8 categories (Dining, Groceries, Transportation, Travel, Shopping, Health, Entertainment, Other), flags receipts that don't add up for review, and shows spending insights.

STACK
- Frontend: React 19 + Vite 8, plain CSS, no router (view in URL hash), no UI library. Allowed additions: motion (animations), lucide-react (icons), Fontsource fonts, @playwright/test.
- Backend: FastAPI + SQLAlchemy + SQLite, cookie JWT auth, camelCase JSON.
- Repo: github.com/gitrobbie/KTPledgeProject (my fork of Aiden's). Working branch: fe/insights-dashboard.
- Locally the OCR model is NOT installed, so uploads land in "review". A seed script (backend/scripts/seed_demo.py) creates ~6 months of fake receipts so charts have data.

API (all under /api)
Auth: POST /auth/register, POST /auth/login, POST /auth/logout, GET /auth/me
Receipts: GET /receipts, POST /receipts (multipart "file"), GET/PATCH/DELETE /receipts/{id}, GET /receipts/{id}/image, GET /categories
Insights (month=YYYY-MM): /insights/categories, /insights/trend?months=6, /insights/merchants?limit=5, /insights/weekdays, /insights/receipt-size, /insights/savings?year=

WHAT EXISTS
Login, receipts list with month navigation, drag-and-drop upload with polling, review tab, receipt editor, and (on the branch) an Insights page wired to all six insights endpoints. It works but looks like generic AI output (cream background, serif headings, forest green).

DESIGN DIRECTION — "Thermal" (light)
The app feels like the receipts it reads. Cool-gray canvas #F6F7F9, white cards with 1px #E2E5EA borders, ink #121417. Color only for data: 8 fixed category colors. Instrument Sans for UI, JetBrains Mono with tabular numbers for all money. 64px monospaced month total with a plain-English insight sentence ("Dining is up 22% — mostly Chipotle"). One torn-receipt edge on the total card. No gradients, purple, glow, emoji icons, or default shadcn look. Motion: 200ms, cubic-bezier(0.23,1,0.32,1), transform/opacity only, reduced-motion respected. Only three animations: receipt "prints in" after processing, category bars re-settle on month change, review rows clear when fixed.

THE PLAN (my structure)
1. Repo + API contract (done, in docs/FRONTEND_BRIEF.md)
2. 2–3 visual references with what to take from each (Thermal mockup, Copilot Money, real thermal receipts)
3. One complete user flow: sign in → Insights → switch months → "3 need review" → fix a receipt in the editor → save → count drops → upload a new receipt → processing card
4. Desktop + mobile requirements at 1440 / 768 / 390 px; content max-width 1120px; editor image pane fixed 400px (fixes a big empty gap on wide screens)
5. Loading (skeleton after 300ms), empty, error (inline + retry), success (toast + undo) states on every screen
6. Executable check: a Playwright e2e test proving the flow, plus screenshots at three widths
7. Build in slices: implement → run → screenshot/inspect → fix → lint/build/test → commit
Slices: setup+tokens+shell, Insights, e2e harness, Receipts list, Editor, Upload, Sign in, animations, critique pass, README.
